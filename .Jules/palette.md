## 2024-05-18 - Modal Component Accessibility Requirements
**Learning:** Custom UI dialogs/modals in the `@dms/web-admin` application require explicitly setting fundamental ARIA roles (`role="dialog"`, `aria-modal="true"`, `aria-labelledby`) and implementing an Escape key event listener to close the modal, in order to comply with accessibility standards.
**Action:** When building or updating custom modals, always include `role="dialog"`, `aria-modal="true"`, dynamic `aria-labelledby`, and ensure keyboard accessibility by binding 'Escape' to the modal's close functionality.## 2024-09-12 - Generic Wrapper ARIA Linkage
**Learning:** Using `React.cloneElement` on children in generic form wrappers (`FormField`) allows for automatic, dynamic `id` and `aria-describedby` generation, guaranteeing accessibility linkage across all usages without requiring manual prop passing at each call site. Merging existing `aria-describedby` from the child is critical to avoid overriding custom hints.
**Action:** Default to automatic `useId` linkage in structural wrapper components rather than expecting developers to manually link `id` and `htmlFor` props on every input.
